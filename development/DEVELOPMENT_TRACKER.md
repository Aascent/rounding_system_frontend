## Synthetic user name-generator bug fix (2026-09-22, follow-up)

- Feedback: the NP roster showed the same person 2-3 times (e.g. "Avery Bishop" at three different emails).
- Root cause found in `packages/contracts/src/admin-data.ts`'s `generatedUsers()`: first name used index `i % 15`, surname used `(i * 3) % 15` - but since 15 divides evenly and `gcd(3, 15) = 3`, that pairing repeats every 15 users _no matter what multiplier is chosen_ (both indices are pure functions of `i mod 15`), so the 78 generated staff only ever produced 15 distinct names, each repeated ~5x. This affected every consumer of `syntheticUsers` (Admin > Users, and now the NP roster, which made it visible for the first time).
- Fixed with a base-15 counter instead: surname index now increments only every 15 users (`Math.floor(i / 15) % 15`) while the first-name index cycles every user (`i % 15`) - the standard way to get all 15 x 15 = 225 combinations before repeating. Verified all 78 generated users (and the 36-entry NP roster) now have unique names; `npm run validate` green (48/48 tests, clean build).
